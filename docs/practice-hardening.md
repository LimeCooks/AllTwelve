# Practice plan editing

Practice plans can now be renamed and rescheduled, and existing segments can be edited for name, entered start time, whole-minute duration, group and coaching focus. Segments can move earlier/later through a collapsed More menu. Reordering preserves entered start times; a warning identifies an out-of-order clock sequence. Legacy single-digit hours and custom groups remain editable. Manual segment changes are labelled as manual rather than claiming an untouched generated plan.

The timeline spans the workspace. Secondary plan details and per-segment actions start collapsed. The read-only preview hides editing controls and is labelled as a preview, not account delivery. A plan deletion requires a separate confirmation. Form changes survive failed saves, and closing a dirty form requires explicit discard; workspace navigation and tab close also guard unsaved work.

GET includes a content version for each plan. PUT and DELETE require that version and use an atomic compare against the original title, date and JSON in the team-scoped write. A stale device receives 409 without overwriting/deleting the latest plan. The owner can download the open draft, then explicitly discard and reload the latest selected plan. No schema migration or rewrite of old plans is needed. Previously open browsers must reload once after this release to obtain versions; rollback code can still read the unchanged storage format.

Generation uses saved gameplan objectives and actual resolved play names; unavailable or ambiguous play references stop generation instead of turning broken references into plausible practice content. Replacing existing segments still requires confirmation. Duration, dates and segment start times are validated on the server.

Validation: all 37 automated tests passed, with the practice integration test expanded to cover simultaneous competing saves, stale save/delete rejection, rename/date/order/duration persistence, invalid times and owner isolation. Local browser checks edited a segment from 15 to 12 minutes, saved its coaching focus, moved it ahead of another segment, renamed the plan, confirmed dirty-form protection, rejected a competing-device overwrite, downloaded the unsaved draft and verified its exact coaching text, then explicitly reloaded the other device's plan. A 390px phone viewport showed the full segment editing form and its save/cancel controls. The single disposable local plan was deleted and every original plan was compared against its pre-test snapshot. No hosted test records were created.

Remaining handoff work includes physical-device use, printed practice scripts, richer play diagram links, optional automatic clock scheduling, and named gameplan-to-practice associations. This release does not claim those workflows are complete.

## Named source association — November 8

Practice generation now uses an explicitly selected named gameplan and pins its ID, title and revision on the server. Manual edits retain that historical source link even when the script is labelled manual. Opening the source follows its stable ID; it does not silently choose another active plan. A changed source is explained in the collapsed source panel. Generation rejects stale/archived/unavailable plans and atomically rechecks the source before saving. Replacing existing segments requires confirmation naming the selected source. Building practice from a gameplan starts a new unsaved practice rather than opening and replacing an unrelated saved practice.

The 91-test suite and type check pass. Isolated production-build browser checks verified two independent plans, source handoff, generated defensive grouping, manual segment preservation, cancelled replacement, archive/restore, competing-tab conflict retention and explicit successful reload. Actual 390px viewport checks covered practice editing and new-gameplan save/cancel controls. These close the named association limitation above; physical-device walkthroughs, printing and richer diagram links remain open.
