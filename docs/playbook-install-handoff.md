# Playbook to Install handoff

The saved-play viewer keeps Add to install collapsed by default. It loads current draft destinations without caching, shows only the play's unit and Team installs, and clears its selection when the viewed play changes or the list refreshes. Request cancellation and source-tagged readiness prevent older play results from enabling the current chooser. Names, units and optional due dates distinguish packages without imposing a weekly cadence.

A synchronous mutation lock prevents overlapping submissions. Success requires a validated server response for the exact destination package containing the exact saved play; an HTTP success alone is insufficient. Messages name both records. The existing server insertion is idempotent, so retries do not add duplicate install entries. Failed reads have an explicit error and Refresh drafts recovery; they do not show a misleading editable empty state. Failed saves retain the selection and leave the saved play untouched.

Manage installs opens the selected package by ID. Install loading checks that exact ID; an unavailable target fails visibly rather than silently choosing another package. Initial-load retry preserves the requested target. Normal navigation to Install still opens its usual list. Published packages are excluded from the chooser, while server-side unit and publication checks remain authoritative if another device changes a destination.

Validation: unit tests cover unit/cadence filtering, published exclusion, blank/failed/malformed reads, exact request IDs, mismatched/partial success responses and conflicting server responses. The real handler/SQLite integration verifies the client and repeated addition yielding one entry. Local browser QA switched between two disposable plays, verified selection reset and incompatible-unit exclusion, added and retried a play, and opened the exact named package showing the correct play. A deliberately malformed disposable package demonstrated disabled adding and successful Refresh drafts recovery after restoration. The controls fit a 390px phone layout. All disposable records were removed; original local playbook and install payloads matched their pre-test snapshots exactly. Hosted owner records were not used for QA.

Remaining: physical device testing of the full install workflow, deeper links to a particular item within an install, and real player accounts/learning permissions and quizzes. This handoff does not implement team delivery or a weekly scheduling policy.
