# Playbook copy and delete safety

Duplicates require the version of the saved play being copied. Its raw diagram/notes and ordered assignments are checked together before and inside the database transaction. The creation ledger, coherent copied record, new assignment IDs and temporary assertion cleanup commit in one batch. Source changes or deletion abort the entire transaction, with no partial copy or creation claim. Published plays can still be copied for revision; publication does not prohibit copying. Confirmed creation retries return their original copy even if the source later changes or is removed.

Deletes require the version presented when the named confirmation opened. The version is frozen at that point and includes assignment content for plays. At commit, empty books/formations must still be empty and deleted plays must still be absent from all installs. A newly added child or install link prevents cascades over that newer work. Own-team scoping and identity checks apply to both operations. Missing versions require reloading, including old clients after deployment. No schema migration is needed.

The confirmation names the record, stays open on failure, disables its outdated action and offers Reload saved records. The in-flight Cancel/close actions are blocked rather than implying that a dispatched operation can be cancelled. The browser also verifies that a confirmed deletion response no longer contains its target. Failed or uncertain network responses should be resolved by reloading; successful hard deletion still has no in-product undo or trash. Full backups remain the recovery path for accidental intentional deletion.

Validation: handler/real-SQL tests inject source diagram/assignment edits between preflight and commit, verify no partial copies/ledger rows, check fresh copies and creation retries, stale/missing versions, new child plays and new install links during deletion, published-source copying, and anonymous/cross-owner rejection. Local browser QA duplicated a disposable play with assignments, confirmed matching copied content with independent assignment IDs, rejected old delete confirmations after newer saves, and reloaded the newer record. Phone controls were visually checked at 390px. QA records and their creation ledger were removed; the original local library and workspace-state hash matched the pre-test baseline. Hosted owner records were not used.

The isolated release rehearsal also copies/retries, rejects a stale delete, and deletes the fresh disposable copy before checking saved records through rollback and forward deployment. Rollbacks to an older handler do not inherit these new version checks.

Remaining: in-product trash/restore, duplicate naming/organization preferences, high-volume library handling and the other private-pilot handoff gates.
