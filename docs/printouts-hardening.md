# Saved-play teaching sheets

Printouts now has its own workflow using the authenticated saved Playbook library. Each checkbox has a unique label target; filters include unit and a real name/formation/playbook search. Selection order is preserved and can be changed without editing or deleting source plays. Selection is explicitly temporary. Export/print settings and per-play selection actions start collapsed.

The preview uses a light paper palette. Its view box fits visible players, routes, rotated coverage and labels rather than the designer's current camera. Hidden opponent geometry stays hidden. Missing diagrams are identified instead of replaced with invented alignments. Notes and assignments come only from the selected saved records. Library errors gate selection/export and provide retry.

Download PDF supports Letter/A4, portrait/landscape and optional notes/assignments. Long teaching content flows onto continuation pages with headers and page numbers. Each play starts a new page. The browser builds the document locally; it does not send play text or diagrams to an outside export service. Browser-native text rendering retains the device's Unicode font support. Export uses high-resolution page images in PDF, so text is visually readable but is not selectable/searchable or tagged. Searchable/vector/tagged output is future work.

The PDF library is pinned to 1.17.1 and loaded only on export. Its official [browser/PDF creation documentation](https://pdf-lib.js.org/) and [release listing](https://github.com/Hopding/pdf-lib/releases) were checked. The app offers a persistent open/download link after preparation when automatic browser download does not open the file. Export is bounded to 25 plays and 100 pages; a limit/failure preserves selection and does not produce a truncated success. Saved source plays are never modified by export.

The previous globally applied print rule hid the body on every screen. It is replaced with rules scoped to Printouts and paper/orientation matching its options. Other tools no longer inherit the Printouts visibility rule. Physical browser/printer behaviour still needs owner verification; direct PDF download is the verified primary output.

Validation: 43 automated tests pass. New geometry tests cover routes, rotated zones, long labels, hidden opponents and immutability; text tests cover unbroken strings, Unicode and paragraph boundaries. Local browser checks selected two independent plays, reordered them, and prepared Letter portrait and A4 landscape from a 390px phone-sized layout. Both real downloaded files were reopened using pypdf and every page rendered using PDFium for visual inspection. Each was four pages, about 1.7 MB, with the expected page dimensions. Rendered output retained the saved route/coverage, 55 numbered Unicode notes, END OF QA NOTES, final position assignments, and a separate honest missing-diagram play. Reordered A4 output began with the undrawn play. The temporary plays and separate QA book were removed, and every original play, book and formation matched its pre-test snapshot. No hosted test content was created.

Remaining: verify actual iPhone/iPad downloads/share sheets and physical printing with the owner. Export selection/preferences are not shared or persisted between sessions. Very large books need a paginated/export workflow beyond the current bounded client export. These are still part of the broader product handoff work.

## Practice PDF workflow — November 8

A saved practice can be prepared as a field-side PDF from Practice Plans → Plan options → Practice printout, or Printouts → Print material → Practice scripts. The latter loads saved practices independently of the play library, uses explicit record selection, and distinguishes load failure from a genuinely empty team. It does not create temporary domain records or change saved scripts.

Print preparation checks the selected saved record and revision again. Missing, duplicate, malformed, failed or stale reads reject export; the owner can reload and review the current record. A failed recheck removes old PDF links. No write is issued by preparation. A 20-second read limit and navigation/close guards cover preparation; failed attempts preserve the saved script and available preview. Open and Save links remain available after successful preparation, supporting device-native printing/share flows rather than assuming an automatic download succeeded.

Letter/A4, portrait/landscape and optional coaching notes are supported. The PDF preserves the saved segment order, entered start times, unscheduled segments and arbitrary group names. Total minutes sum segment durations, not gaps or elapsed practice time. Out-of-order entered times are flagged without silently rescheduling. Recorded source-gameplan names survive manual changes and print as historical origins. Long notes flow to continuation pages with context and page numbering; exports exceeding 100 pages fail rather than silently truncating.

Rendering uses the same local PDF dependency and browser-native fonts as saved-play sheets. Practice PDFs are high-resolution page images; text is not selectable/searchable or tagged. No coaching text is sent to an external export service. The on-screen preview is bounded so lengthy notes do not bury preparation controls.

Validation: 100 automated tests pass. New tests cover exact saved IDs/revisions, blank/error/malformed lists, invalid dates/totals/segments, custom groups, unscheduled and out-of-order timing, complete long-note pagination, note omission, paper sizes, maximum-page rejection and source immutability. The actual PDF module ran with a real native canvas backend to produce Letter portrait (2 pages) and A4 landscape (3 pages). Both PDFs were reopened with pypdf and every page rendered with PDFium; all 55 numbered teaching notes, accented terminology, END OF COACHING NOTES and the final special-teams segment were visually checked. This proves the shared rendering code's output, not a physical device download.

An isolated production-build browser prepared a PDF through the app, exposed persistent Open/Save links, and kept every saved practice record identical. Injected failed reads removed download links and displayed an error. A competing saved revision rejected stale preparation; explicit reload selected the newer named record. Phone layout and physical device/printer checks remain separate gates.

Final UI verification: in an actual 390px viewport, the dialog fits within the screen, the long-note preview scrolls inside a bounded paper panel, and preparation/open/save controls remain reachable. A4 landscape with notes disabled prepared successfully through the real browser module. Both the dedicated Printouts library and the collapsed Practice Plans action were exercised, including the latter's recorded gameplan source. Switching back to saved-play sheets remained functional. Every local practice record was compared unchanged after the final export checks. Evidence: outputs/practice-print-browser-report.json and outputs/practice-print-phone.png.
