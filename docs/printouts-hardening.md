# Saved-play teaching sheets

Printouts now has its own workflow using the authenticated saved Playbook library. Each checkbox has a unique label target; filters include unit and a real name/formation/playbook search. Selection order is preserved and can be changed without editing or deleting source plays. Selection is explicitly temporary. Export/print settings and per-play selection actions start collapsed.

The preview uses a light paper palette. Its view box fits visible players, routes, rotated coverage and labels rather than the designer's current camera. Hidden opponent geometry stays hidden. Missing diagrams are identified instead of replaced with invented alignments. Notes and assignments come only from the selected saved records. Library errors gate selection/export and provide retry.

Download PDF supports Letter/A4, portrait/landscape and optional notes/assignments. Long teaching content flows onto continuation pages with headers and page numbers. Each play starts a new page. The browser builds the document locally; it does not send play text or diagrams to an outside export service. Browser-native text rendering retains the device's Unicode font support. Export uses high-resolution page images in PDF, so text is visually readable but is not selectable/searchable or tagged. Searchable/vector/tagged output is future work.

The PDF library is pinned to 1.17.1 and loaded only on export. Its official [browser/PDF creation documentation](https://pdf-lib.js.org/) and [release listing](https://github.com/Hopding/pdf-lib/releases) were checked. The app offers a persistent open/download link after preparation when automatic browser download does not open the file. Export is bounded to 25 plays and 100 pages; a limit/failure preserves selection and does not produce a truncated success. Saved source plays are never modified by export.

The previous globally applied print rule hid the body on every screen. It is replaced with rules scoped to Printouts and paper/orientation matching its options. Other tools no longer inherit the Printouts visibility rule. Physical browser/printer behaviour still needs owner verification; direct PDF download is the verified primary output.

Validation: 43 automated tests pass. New geometry tests cover routes, rotated zones, long labels, hidden opponents and immutability; text tests cover unbroken strings, Unicode and paragraph boundaries. Local browser checks selected two independent plays, reordered them, and prepared Letter portrait and A4 landscape from a 390px phone-sized layout. Both real downloaded files were reopened using pypdf and every page rendered using PDFium for visual inspection. Each was four pages, about 1.7 MB, with the expected page dimensions. Rendered output retained the saved route/coverage, 55 numbered Unicode notes, END OF QA NOTES, final position assignments, and a separate honest missing-diagram play. Reordered A4 output began with the undrawn play. The temporary plays and separate QA book were removed, and every original play, book and formation matched its pre-test snapshot. No hosted test content was created.

Remaining: verify actual iPhone/iPad downloads/share sheets and physical printing with the owner. Export selection/preferences are not shared or persisted between sessions. Very large books need a paginated/export workflow beyond the current bounded client export. These are still part of the broader product handoff work.
