# Private conversation persistence

The former Messages screen created named channel/direct-recipient labels without real membership, claimed messages were sent, cleared drafts before writes succeeded, and replaced an entire JSON store on each action. The owner-private pilot now records private conversations through an authenticated conversation service. It explicitly says team delivery is not connected. Recipient entry, simulated delivery, decorative attachment tools and reaction controls have been removed rather than presented as working communication features.

`/api/messages` reads/writes the signed-in owner's team-scoped `private-conversations-v3` workspace record. Authors and ISO timestamps come from trusted server identity and clock; client author fields are ignored. Atomic compare-and-swap appends merge competing saves. Stable client request IDs make an uncertain save retry idempotent, and conflicting ID reuse is rejected. Generic workspace writes cannot replace this record or forge authors. Every read and write requires owner workspace access; no browser-supplied team ID is accepted. There is no schema migration, and full backups already include the workspace-state table.

First-time teams start with zero conversations and messages. Earlier `message-centre-v2` records remain byte-for-byte unchanged and appear in a collapsed read-only archive when they contain messages. Old member names do not grant access or prove delivery. An unreadable legacy record gets an explicit warning; corrupt current storage blocks saves instead of becoming an apparently empty store.

Drafts remain until a confirmed successful save, are held separately per conversation during the open session, and trigger navigation/tab-close warnings. A refresh preserves open drafts. Failed reads gate editing and provide retry/draft-download actions. Names and text have explicit limits (100 conversations, 2,000 messages per conversation, 4,000 characters per message and 750,000 UTF-8 bytes for the current store). A limit returns an error without discarding drafts. Large-scale conversation pagination/storage remains future work.

Validation: 40 automated tests pass. Conversation integration tests exercise real SQL, blank reads, trusted authors, simultaneous appends, retry deduplication, conflicting IDs, duplicate names, invalid input, generic-write rejection, anonymous access and cross-owner rejection. They compare the unchanged earlier record. Local browser checks created a disposable conversation, saved a message, deliberately made only that test record unreadable, observed a failed save preserving its exact draft, restored the test row, and retried successfully. Exactly two messages were present. A refresh retained them; Keep editing preserved a navigation draft. At 390px the page stayed inside the viewport and the full-width save button was reachable above mobile navigation. The test conversation was removed and both current and legacy storage matched their pre-test snapshots. No hosted test records were created.

The release rehearsal also saves a private conversation/message, retries it without duplication, and reads the preserved record across candidate/rollback/forward transitions and full backup verification. The previous build has no UI for this new record; it retains the data and the forward build exposes it again.

Remaining: staff/player membership, explicit conversation access policies, invitations, notifications, attachments, reactions, message editing/deletion and delivery/read receipts are not implemented by this release. Before enabling other team accounts, define visibility for these owner-private records and enforce it server-side. Private saved messages are not a replacement for those full communication workflows, which remain part of the broader handoff work.
